# Монтаж: врезки, звук и эффекты

План превращения конвейера из «нарезать и одеть по правилам» в «описать произвольный
монтаж и отрендерить его». Код и идентификаторы остаются английскими, как во всём
репозитории; этот документ — на русском, потому что он про решения, а не про API.

Ведущее требование: **возможность собирать нетривиальные пользовательские сценарии**.
Это значит, что целью является не список фич («добавить кроссфейд», «добавить
вотермарк»), а словарь, из которого сценарии собираются. Каждый раз, когда план
предлагает выбор между «частный случай» и «примитив, из которого частный случай
складывается», выбирается второе.

---

## 1. Что уже есть

`app/domain/composition.py` — это EDL, и его докстринг прямо называет тот случай,
ради которого он написан:

> It stops holding up the moment a second source is involved — an insert, a split
> screen, a hook taken from elsewhere in the video.

Что из этого работает сегодня:

| | Модель | Компилятор | Кто это порождает |
| --- | --- | --- | --- |
| Сегменты из разных файлов | `Segment.source_path` — свой у каждого | `one_pass_args` даёт отдельный `-i` на сегмент | **никто** |
| Наложение видео (full / PiP) | `Insert` | `_insert_chains` (`compiler.py:626`) | `inserts.choose_inserts` по тегам |
| Музыка с дакингом | `MusicBed` | `_audio_chains` + `sidechaincompress` | `audio.choose_music`, тег `music` |
| Точечные звуки | `SoundEffect` | микс через `amix`, таймлайн не двигается | `audio.choose_effects`, только на склейках |
| Проекция времени источника на выход | `Composition.timeline()` | — | — |
| Субтитры и заголовок | `SubtitleSpec` → `.ass` | `_look_chain` | `subtitles.make_subtitle_cues` |

Два свойства модели, на которых держится всё дальнейшее, и их стоит проговорить,
потому что расширения обязаны их сохранить:

* **Сегмент — единица кэша.** В нём лежит только то, что выводится из источника.
  Всё, что стиль, вынесено за его пределы (`_look_chain`) именно для того, чтобы
  смена оформления не инвалидировала отрендеренный фрагмент.
* **Время абсолютно в источнике и неявно на выходе.** Сегмент знает свои секунды
  в своём файле; где он окажется в клипе — следствие того, что перед ним. При
  перемещении сегмента ничего не перенумеровывается.

## 2. Чего не хватает

**2.1. Мультиисточниковую композицию никто не собирает.** Единственная фабрика —
`single_source()` (`composition.py:301`), и `plan_vertical_clip()`
(`compiler.py:215`) ходит только в неё. Монтаж из нескольких файлов легален в
типах и недостижим на практике.

**2.2. Композиция нигде не хранится.** `handlers/render.py` собирает её из опций
джобы, рендерит и выбрасывает. Следствия: ручной правке негде жить; нет способа
перерендерить один клип; кэш фрагментов и стратегия `two_stage`, описанные в
докстринге компилятора как окупающиеся при повторных рендерах, окупаться не на чем.

**2.3. Эффектов нет.** `_look_chain` (`compiler.py:666`) — захардкоженные
`eq=contrast=1.04:saturation=1.08` и `unsharp` на весь клип. `_concat`
(`compiler.py:605`) умеет только встык. У сегмента нет ни скорости, ни зума, ни
собственного грейда.

И три частности, прямо относящиеся к задаче:

* у врезки **всегда выбрасывается звук** — сознательное решение `_insert_chains`,
  чтобы не разъезжались субтитры;
* источником врезки может быть только библиотека — не произвольный файл и не
  другое место того же исходника;
* `SoundEffect` ставится только автоматически и только на склейки, под потолком
  политики; произвольной звуковой дорожки в нужную секунду нет.

## 3. Целевая модель

Расширения `app/domain/composition.py`. Всё — фризнутые датаклассы, как сейчас;
все новые поля со значениями по умолчанию, дающими **текущее поведение
байт-в-байт**. Это не вежливость, а способ проверки: пока дефолты дают тот же
граф фильтров, существующие тесты компилятора — регрессионный щит.

### 3.1. Сегмент

```python
@dataclass(frozen=True)
class Segment:
    source_path: str
    source_start_sec: float
    source_end_sec: float
    layout: str = LAYOUT_BLUR
    companion_path: str | None = None
    companion_start_sec: float = 0.0

    # НОВОЕ
    speed: float = 1.0                      # >1 быстрее; меняет длину на выходе
    effects: tuple[Effect, ...] = ()        # внутрисегментные, попадают в кэш
    transition: Transition | None = None    # переход ВХОДА в этот сегмент
    mute: bool = False                      # выкинуть звук этого куска

    @property
    def duration_sec(self) -> float:        # как сейчас: длина в источнике
        return round(self.source_end_sec - self.source_start_sec, 3)

    @property
    def output_duration_sec(self) -> float: # НОВОЕ: сколько занимает в клипе
        return round(self.duration_sec / self.speed, 3)
```

`duration_sec` сохраняет нынешний смысл (им пользуются `_add_input` и `anullsrc`
в `_segment_audio_chain`), а `Composition.duration_sec` и `timeline()`
переключаются на `output_duration_sec`. При `speed == 1.0` это тождество, так что
изменение невидимо для всего существующего.

### 3.2. Эффект

Реестр, а не перечисление. Новый эффект — новая запись в реестре, а не новая
ветка в компиляторе; это и есть механизм расширения под сценарии.

```python
# app/domain/effects.py
@dataclass(frozen=True)
class Effect:
    name: str
    params: Mapping[str, float | int | str] = field(default_factory=dict)

    def __post_init__(self) -> None:
        spec = REGISTRY.get(self.name)
        if spec is None:
            raise ValueError(f"unknown effect {self.name!r}")
        spec.validate(self.params)
```

```python
# app/adapters/media/effects.py — единственное место, знающее про ffmpeg
@dataclass(frozen=True)
class EffectSpec:
    name: str
    scope: str                 # "segment" | "look"
    validate: Callable[[Mapping], None]
    chain: Callable[[comp.Canvas, Mapping], str]   # кусок цепочки без меток
```

Стартовый набор (`scope="segment"`): `zoom` (ken burns через `zoompan`),
`mirror` (`hflip`), `grayscale`, `freeze` (`tpad`/`loop`), `shake`
(`crop` с осцилляцией по `t`), `reverse`. `scope="look"`: `vignette`, `grade`,
`glow`, `chroma`.

Скорость (`speed`) намеренно **не** эффект: она меняет длину на выходе, то есть
участвует в арифметике таймлайна, а не только в цепочке фильтров. Смешивать эти
два вида нельзя — иначе любая правка эффекта станет ретаймингом.

### 3.3. Переход

```python
@dataclass(frozen=True)
class Transition:
    kind: str = "cut"             # cut | fade | wipeleft | wiperight | flash | slideup
    duration_sec: float = 0.0     # cut — всегда 0
```

Переход укорачивает клип: `xfade` накладывает соседние сегменты внахлёст.

```python
@property
def duration_sec(self) -> float:   # Composition
    total = sum(s.output_duration_sec for s in self.segments)
    overlap = sum(s.transition.duration_sec for s in self.segments[1:] if s.transition)
    return round(total - overlap, 3)
```

### 3.4. Врезка

```python
@dataclass(frozen=True)
class Insert:
    kind: str
    source_path: str
    at_sec: float
    duration_sec: float
    source_start_sec: float = 0.0
    still: bool = False

    # НОВОЕ
    with_audio: bool = False      # врезка приносит свой звук
    gain_db: float = 0.0
    duck_under_db: float = 0.0    # на сколько приглушить основу под врезкой
    effects: tuple[Effect, ...] = ()
    opacity: float = 1.0
    fade_sec: float = 0.0
```

### 3.5. Оформление и накладки

```python
@dataclass(frozen=True)
class Look:
    contrast: float = 1.04        # ровно нынешние значения _look_chain
    saturation: float = 1.08
    brightness: float = 0.0
    gamma: float = 1.0
    sharpen: bool | None = None   # None — следовать AUTOCLIPS_RENDER_SHARPEN
    effects: tuple[Effect, ...] = ()

@dataclass(frozen=True)
class Overlay:
    kind: str                     # "image" | "text"
    at_sec: float
    duration_sec: float
    source_path: str | None = None       # image
    text: str | None = None              # text
    x_percent: float = 50.0
    y_percent: float = 18.0
    scale: float = 1.0
    opacity: float = 1.0
```

Текстовые накладки идут **дополнительными событиями в тот же `.ass`**, а не через
`drawtext`: libass уже в цепочке, шрифты уже подключены (`filters.fontsdir_arg`),
и текстовый слой обходится в ноль дополнительных фильтров. Картиночные накладки
идут через `overlay`, рядом с врезками.

### 3.6. Композиция

```python
@dataclass(frozen=True)
class Composition:
    segments: tuple[Segment, ...]
    canvas: Canvas = field(default_factory=Canvas)
    inserts: tuple[Insert, ...] = ()
    subtitles: SubtitleSpec | None = None
    music: tuple[MusicBed, ...] = ()      # было: MusicBed | None
    effects: tuple[SoundEffect, ...] = ()
    look: Look = field(default_factory=Look)
    overlays: tuple[Overlay, ...] = ()
    crf: int = 23
    version: int = VERSION
```

`music` становится кортежем: одна дорожка под весь клип — частный случай, а
«музыка до врезки, другая после» или «войсовер поверх» — ровно то, ради чего
это делается. `MusicBed` получает `at_sec` и `duration_sec` (`None` = весь клип),
и тогда войсовер — это `MusicBed` без дакинга в нужном окне, а не новая сущность.

## 4. Этап 1 — EDL, который переживает рендер

Без этого этапа ручные правки некуда класть. Он же самый дешёвый и полезен сам по
себе.

**4.1. Сериализация.** `Composition.to_dict()` / `Composition.from_dict()` —
чистые, в домене, рядом с самими датаклассами. `VERSION` уже заведён под это:
`from_dict` с чужой версией не пытается угадать, а сообщает о несовместимости,
и вызывающий перепланирует клип с нуля.

**Пути хранятся относительно `media_root()`** и разворачиваются при загрузке.
Абсолютные пути переживут ровно до первого пересоздания контейнера или переезда
тома — это тот случай, когда ошибка проявится через месяц и на чужих данных.

**4.2. Хранение.** Миграция добавляет в `clips`:

```python
composition_json: Optional[str] = Field(default=None)   # сериализованный EDL
composition_version: Optional[int] = Field(default=None)
edited_at: Optional[datetime] = Field(default=None)     # None = не тронут руками
```

`alembic revision --autogenerate -m "clip composition"`; `tests/test_migrations.py`
поймает расхождение моделей и миграций.

**4.3. Развилка в рендере.** В `handle_render`:

```
есть composition_json нужной версии  →  рендерить его
иначе                                →  планировать как сейчас, и сохранить результат
```

Второй путь важен не меньше первого: после первого же рендера у каждого клипа
появляется EDL, который можно показать и править. Автопланнеры (`_dress`)
применяются только на пути планирования — клип, тронутый руками, не переодевается
за спиной у человека.

**4.4. Ручки.**

```
GET    /api/clips/{id}/composition          → EDL
PUT    /api/clips/{id}/composition          → заменить целиком (с валидацией)
DELETE /api/clips/{id}/composition          → сбросить к автопланированию
POST   /api/clips/{id}/render               → перерендерить один клип
```

`POST /render` ставит обычную задачу `TaskKind.RENDER` — очередь, ретраи и
прогресс уже есть и менять их не нужно.

**4.5. Превью.** `POST /api/clips/{id}/render?preview=1` — 540×960, `ultrafast`,
`crf 30`, без `unsharp`, в отдельный файл. Порядка десяти раз быстрее доставочного
рендера. Без него ручной монтаж нерабочий: цикл правки, в котором каждая итерация
стоит минуту, никто крутить не будет.

Зацепка для этого уже есть: `encoders.encoder_args()` принимает `fast=`, так что
превью — это набор аргументов рядом с существующими, а не отдельный путь рендера.

*Объём: сериализация и тесты к ней, одна миграция, развилка в хендлере, четыре
ручки, превью-профиль в `encoders`.*

## 5. Этап 2 — словарь операций

`app/domain/editing.py` — чистые функции `Composition -> Composition`, в том же
стиле, что `inserts.py` и `audio.py`: значения на входе, значения на выходе,
никакой БД и никакого ffmpeg.

Операции делятся на два класса, и это деление — главное в этапе.

### 5.1. Операции, не меняющие таймлайн

Тривиальны: заменяют поле и возвращают новую композицию.

```python
add_insert(comp, insert)            drop_insert(comp, index)
add_sound(comp, effect)             drop_sound(comp, index)
add_music(comp, bed)                drop_music(comp, index)
add_overlay(comp, overlay)          drop_overlay(comp, index)
set_look(comp, look)
set_segment_effects(comp, index, effects)      # эффекты без изменения длины
set_subtitles(comp, spec)
```

### 5.2. Операции, меняющие таймлайн

```python
splice_in(comp, at_sec, segment)               # врезка со сдвигом
remove_range(comp, start_sec, end_sec)
split_segment(comp, at_sec)
move_segment(comp, index, to_index)
trim_segment(comp, index, *, head_sec=0, tail_sec=0)
set_speed(comp, index, factor)
set_transition(comp, index, transition)
```

Каждая двигает то, что закреплено за выходным временем: врезки, звуки, музыку,
накладки и **субтитровые реплики** (`SubtitleCue` живут в выходном времени —
`subtitles.py:60`). Делать этот пересчёт в каждой операции отдельно — гарантия
того, что одна из семи его забудет.

Поэтому механизм один. Операция возвращает новые сегменты **и кусочно-линейное
отображение старого выходного времени в новое**, а общий хелпер прикладывает его
ко всем якорям:

```python
@dataclass(frozen=True)
class Retime:
    """Кусочно-линейная карта старого выходного времени в новое."""
    pieces: tuple[tuple[float, float, float], ...]   # (from_sec, shift, scale)

    def __call__(self, at_sec: float) -> float: ...

def _rebuilt(comp, segments, retime: Retime) -> Composition:
    """Единственное место, где якоря переезжают вслед за таймлайном."""
```

Примеры карт, чтобы было видно, насколько они мелкие:

| Операция | Карта |
| --- | --- |
| `splice_in(at, d)` | `t < at → t`; `t ≥ at → t + d` |
| `remove_range(a, b)` | `t < a → t`; `a ≤ t < b → a`; `t ≥ b → t - (b - a)` |
| `set_speed(i, k)` | до сегмента `i` без изменений; внутри — сжатие в `k`; после — сдвиг |
| `set_transition(i, d)` | всё после начала сегмента `i` сдвигается на `-d` |

Одна функция `Retime`, семь операций по несколько строк, и один тест на каждую
карту. Правило сохранения таймлайна проверяется одним свойством: слово, звучащее
в секунде `x` источника, после любой последовательности операций остаётся
напротив той же картинки.

*(Альтернатива — привязывать накладки не к абсолютной секунде, а к
`(segment_id, offset)`, тогда пересчёт не нужен вовсе. Это чище, но требует
стабильных идентификаторов сегментов и переписывания автопланнеров, которые
сегодня считают абсолютные секунды из субтитровых реплик. Если перестановки
сегментов станут частой операцией — стоит вернуться к этому.)*

### 5.3. Откуда берётся врезаемый материал

Источник — отдельное понятие, разрешаемое сервисным слоем в путь:

```python
{"kind": "asset",      "asset_id": 14}                       # библиотека
{"kind": "job_source", "start_sec": 412.5, "end_sec": 415.5} # исходник этой же джобы
{"kind": "clip",       "clip_id": 87}                        # готовый клип
{"kind": "upload",     "upload_id": "..."}                   # разовый файл
```

`job_source` — самый ходовой приём и то, чего сейчас нельзя сделать вообще никак:
взять сильный момент из середины часового видео и поставить его хуком в первые
секунды клипа.

### 5.4. Звук врезки

`_insert_chains` сегодня глушит звук врезки намеренно. Чтобы включить его, не
сломав выравнивание:

1. `_insert_chains` возвращает не только цепочки, но и карту `insert -> input
   index` (вход уже добавлен с `-ss/-t`, у него есть `:a`);
2. `_audio_chains` для врезок с `with_audio` подмешивает `[{i}:a]` тем же путём,
   что и `SoundEffect`: `adelay` до `at_sec`, `volume`, в общий `amix`;
3. `duck_under_db != 0` добавляет к основе `volume=enable='between(t,…)'` —
   основа приглушается ровно на окно врезки;
4. врезку **без** звуковой дорожки надо отличать от врезки со звуком — то есть
   на неё придётся потратить `ffprobe_has_audio`, от которого `render()` сегодня
   сознательно уклоняется. Тратить только на врезки с `with_audio=True`.

Таймлайн при этом не двигается: звук врезки — ещё один вход `amix`, ровно как
`SoundEffect`. Это и есть причина, по которой субтитры остаются на месте.

*Объём: `editing.py` с `Retime` и операциями, резолвер источников в
`services/assets.py` + новый `services/editing.py`, ручка операций, правки в
`_insert_chains` / `_audio_chains`.*

## 6. Этап 3 — эффекты

Три слоя, и их нельзя смешивать: они бьют в разные места конвейера и по-разному
относятся к кэшу фрагментов.

| Слой | Где применяется | Кэш | Цена |
| --- | --- | --- | --- |
| `Look` и `Overlay` | `_look_chain`, после склейки | не влияет — слой для того и вынесен | низкая |
| `Segment.effects`, `speed` | внутри цепочки сегмента | **обязан войти в ключ `fragment_path`** | средняя |
| `Transition` | вместо `_concat` | ломает `concat -c copy` | высокая |

### 6.1. Look и накладки

`_look_chain` перестаёт быть захардкоженным и собирается из `composition.look`.
Дефолтный `Look()` обязан давать ровно нынешнюю строку — это проверяется тестом,
сравнивающим граф с эталоном.

Накладки-картинки добавляются как входы рядом с врезками; текстовые уходят в
`.ass` через расширение `write_ass_file` дополнительными событиями со своим
стилем.

### 6.2. Эффекты сегмента и скорость

Цепочка сегмента (`_segment_video_chain`) после компоновки в канвас прогоняет
эффекты в порядке объявления, затем `setpts=PTS/{speed}`; аудио получает
`atempo`, разложенный на множители внутри `[0.5, 2.0]` (ffmpeg не принимает
больше за раз).

**Ловушка, которую надо закрыть в том же коммите:** `fragment_path`
(`compiler.py:771`) собирает ключ кэша из всего, что формирует фрагмент. Добавить
сегменту эффекты и не добавить их в ключ — значит начать молча отдавать старую
картинку. В материал ключа идут `speed` и нормализованное представление
`effects`; `look`, `overlays` и `transition` в ключ **не** идут, потому что
применяются после склейки.

### 6.3. Переходы

Единственное по-настоящему инвазивное место.

`xfade` накладывает сегменты внахлёст и укорачивает таймлайн, а `two_stage`
склеивает фрагменты демультиплексором `concat` без перекодирования — наложения
там сделать негде. Поэтому:

* при наличии хотя бы одного не-`cut` перехода `choose_strategy` форсит
  `STRATEGY_ONE_PASS`. Прецедент есть: смешанные лэйауты точно так же форсят
  `two_stage`;
* склейка перестаёт быть одним n-арным `concat` и становится сверткой: аккумулятор
  плюс очередной сегмент — либо `concat=n=2`, либо `xfade`/`acrossfade` со
  смещением, накопленным по предыдущим. `offset` для `xfade` считается по уже
  собранной длине аккумулятора;
* **когда все переходы `cut`, путь остаётся прежним** — один `concat` на все
  сегменты. Без этого условия нынешние тесты компилятора начнут падать на
  изменившемся графе, и правильно сделают.

`flash` — не `xfade`, а короткая засветка на стыке (`xfade=transition=fadewhite`
либо накладка): называть её переходом удобно, реализуется отдельной веткой.

*Объём: `domain/effects.py` + `adapters/media/effects.py` с реестром, переработка
`_look_chain` и `_segment_video_chain`, свертка вместо `_concat`, расширение ключа
кэша, расширение `write_ass_file`.*

## 7. Этап 4 — сценарии

То, ради чего этапы 1–3 делались словарём, а не набором фич. Сценарий — это
именованный список тех же операций, но с **селекторами вместо литералов**,
применяемый к каждому клипу джобы автоматически.

```yaml
name: hook-first
steps:
  - op: splice_in
    at_sec: 0
    source: { kind: job_source, pick: loudest, duration_sec: 3.0 }
    layout: fill
    effects: [{ name: zoom, from: 1.0, to: 1.12 }]
  - op: set_transition
    segment: 1
    transition: { kind: flash, duration_sec: 0.2 }
  - op: add_sound
    at_sec: 0
    source: { kind: asset, tag: sfx, pick: lru }
  - op: add_overlay
    kind: text
    text: "{title}"
    at_sec: 0.2
    duration_sec: 2.3
  - op: set_look
    preset: punchy
```

Селекторы (`pick: loudest`, `pick: lru`, `tag: …`) разрешаются на этапе
планирования против анализа исходника и библиотеки — тем же кодом, который уже
есть в `cutting/scenes.py` (громкость) и `assets.options_for_planner` (ротация).

Нынешние `inserts.choose_inserts` и `audio.choose_*` при этом становятся
сценариями по умолчанию и остаются на месте: профили продолжают работать, а
сценарий — это способ описать свой профиль, не трогая код.

Оговорка: проектирование DSL — классическое место для расползания объёма.
Этап 4 стоит начинать только когда 1–3 в работе и видно, какие сценарии люди
реально собирают руками. Первые три этапа самодостаточны; этот — надстройка.

## 8. API

```
GET    /api/clips/{id}/composition            EDL клипа
PUT    /api/clips/{id}/composition            заменить целиком
POST   /api/clips/{id}/composition/ops        применить список операций
DELETE /api/clips/{id}/composition            сбросить к автопланированию
POST   /api/clips/{id}/render                 перерендерить (?preview=1)
GET    /api/effects                            реестр эффектов и переходов
```

Операции — то, что правит человек, поэтому пересчёт таймлайна делает сервер:
клиент присылает намерение, а не пересчитанные секунды.

```json
{"ops": [
  {"op": "splice_in", "at_sec": 0,
   "source": {"kind": "job_source", "start_sec": 412.5, "end_sec": 415.5},
   "layout": "fill"},
  {"op": "set_transition", "segment": 1,
   "transition": {"kind": "flash", "duration_sec": 0.2}},
  {"op": "add_insert", "at_sec": 6.0, "duration_sec": 2.5, "kind": "broll_pip",
   "source": {"kind": "asset", "asset_id": 14},
   "with_audio": true, "gain_db": -6, "duck_under_db": -8},
  {"op": "set_speed", "segment": 0, "factor": 1.15},
  {"op": "add_overlay", "kind": "text", "text": "ЧАСТЬ 1",
   "at_sec": 0, "duration_sec": 2.0, "y_percent": 18}
]}
```

Ответ — новый EDL целиком. Клиенту не нужно уметь ретаймить, а значит две
реализации одной арифметики не разойдутся.

## 9. UI

Дорожка в карточке клипа (`webapp/src/pages/JobDetail.tsx`) либо отдельная
страница редактора:

## 10. Ловушки

Собраны отдельно, потому что каждая из них проявляется не сразу и не на том, кто
её сделал.

1. **Ключ кэша фрагментов.** `speed` и `effects` сегмента обязаны войти в
   `fragment_path`, `look`/`overlays`/`transition` — обязаны не войти. Ошибка в
   первую сторону отдаёт старую картинку молча.
2. **Пути в сохранённом EDL** — только относительно `media_root()`.
3. **`-shortest`** в `_delivery_tail` на одном проходе: врезка со звуком,
   заканчивающаяся после видео, не должна удлинять клип. `amix duration=first`
   это уже держит, но проверить тестом.
4. **`loudnorm` в один проход** нормализует по первым секундам. С появлением
   войсоверов и звучащих врезок разброс громкости вырастет; если станет слышно —
   переходить на двухпроходный `loudnorm` с измерением на первом проходе.
5. **`atempo`** в старых сборках ffmpeg принимает множитель только из
   `[0.5, 2.0]`; новые допускают шире, но проект собирается и под Windows, где
   версия какая угодно. Раскладывать на цепочку множителей внутри диапазона —
   это работает везде и ничего не стоит.
6. **`xfade` требует совпадения размера, формата и fps** у обоих входов. После
   цепочек сегментов это так, но при добавлении эффектов, меняющих формат
   (например, `format=gray`), — уже нет. Нормализовать `format` в конце цепочки
   сегмента.
7. **Ограничения `one_pass_max_segments` / `one_pass_max_inserts`** («граф,
   который никто не может прочитать, — граф, который никто не может
   отладить») смонтированный вручную клип будет пробивать регулярно. При
   переходах уйти в `two_stage` нельзя — значит, для них лимит не применяется, и
   это стоит записать явно, а не обнаружить.
8. **Клип, тронутый руками, не переодевается автоматикой.** `edited_at != None`
   должен исключать клип из `_dress` и из пересборки джобы, иначе правки
   исчезнут при следующем запуске планирования.

## 11. Тесты

В нынешнем стиле: домен — чистыми значениями, компилятор — сравнением строки

  операций стоит напротив той же картинки; операции на границах (врезка в 0,
  в конец, внутрь сегмента, ровно на стык).

  двигает таймлайн.
* `tests/test_effects.py` (новый) — реестр: валидация параметров, неизвестный

## 12. Порядок

| Этап | Даёт | Зависит от |
| --- | --- | --- |
| 1. Хранимый EDL | перерендер клипа, превью, место для правок | — |
| 2. Словарь операций | врезки со сдвигом и поверх, звук врезки, произвольные источники | 1 |
| 3. Эффекты | look, эффекты сегмента, скорость, переходы | 1 (2 — для ручного управления) |
| 4. Сценарии | нетривиальные сценарии без кода | 1–3 |

Внутри третьего этапа порядок тоже не произволен: `Look` → эффекты сегмента →
переходы, от дешёвого и безопасного к тому, что трогает склейку и стратегию.

Проверка на каждом шаге одна и та же: композиция без ручных правок обязана
рендериться ровно так же, как до изменения. Пока это так, конвейер, который
работает сегодня, не становится заложником редактора.
