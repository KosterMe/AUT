2. **Циклы в `after`/`before`.** Валидация при сохранении сценария, а не при
   рендере. Топологическая сортировка, цикл — внятная ошибка с именами
   элементов.
3. **Переполнение позвоночника** на коротком клипе — не исключение, а норма
   (§3.1). Политика вытеснения обязана быть, иначе получится либо обрезанный
   клип молча, либо упавший рендер на ровном месте.
4. **Пути в сценариях и EDL** — только относительно корня медиа. Абсолютные
   переживут до первого пересоздания контейнера.
5. **Путь из запроса** валидировать на принадлежность корню. Иначе сервис читает
   любой файл по просьбе клиента.
6. **`xfade` требует совпадения размера, формата и fps** обоих входов. Эффект,
   меняющий формат (`format=gray`), это ломает — нормализовать формат в конце
   цепочки сегмента.
7. **`atempo`** в старых сборках принимает только `[0.5, 2.0]` — раскладывать на
   цепочку множителей.
8. **`loudnorm` в один проход** нормализует по первым секундам. С войсоверами и
   звучащими врезками разброс вырастет; если станет слышно — двухпроходный.
9. **`zoompan` считает по кадрам, а не по секундам** и дрожит на медленном зуме.
   Проверить зондом (§6.2) до того, как класть в пресеты.
10. **Размер графа.** Смонтированный сценарий с десятком слоёв даёт граф, который
    невозможно читать. Нынешние лимиты `one_pass_max_*` («граф, который никто не
    может прочитать, — граф, который никто не может отладить») надо пересмотреть
    осознанно, а не обнаружить.
11. **Версия сценария и версия EDL — разные версии.** Обе нужны, и путать их
    нельзя: сценарий переживает рефакторинг модели, EDL переживает рефакторинг
    рендерера.

## 10. Тесты

В нынешнем стиле: домен — значениями, адаптер — сравнением строки графа.

* **Раскладка** — флексбокс позвоночника: фиксированные, эластичные, переполнение,
  вытеснение, `min`/`max`.
* **Якоря** — каждый режим; поведение на 30/90/180 с; топологический порядок;
  цикл отвергается.
* **Правила** — переносятся существующие тесты `test_inserts.py` и
  `test_audio.py`: все ограничения (хук, зазор, доля, ротация) обязаны выжить
  дословно.
* **Компиляция** — золотые файлы: сценарий + факты → EDL. Читаемый JSON в
  репозитории, diff показывает регрессию наглядно.
* **Интерполяция** — одна спецификация, две реализации (Python и TypeScript),
  один набор векторов. Иначе схема в редакторе разойдётся с рендером, и это будет
  незаметно.
* **Граф фильтров** — статический `Frame` даёт ту же строку, что сегодня;
  анимированный — ожидаемое выражение; `speed` в ключе кэша, `look` — нет.
* **Миграция профилей** — четыре встроенных сценария дают тот же EDL, что нынешние
  профили на тех же фактах. Это главный тест всей работы.

## 11. Этапы

| | Что | Результат | Риск |
| --- | --- | --- | --- |
| **0** | Зонд возможностей ffmpeg | таблица §6.2 по фактам, а не по документации | — |
| **1** | Выделение сервиса | `cutter` рендерит клипы по HTTP, поведение не изменилось | средний: переезд без изменения поведения |
| **2** | Модель и компилятор | `compile(scenario, facts)`, встроенные сценарии, золотые тесты | низкий: чистый домен |
| **3** | Composition v2 и слои | `Frame` с трансформацией, произвольный z-порядок | высокий: трогает рендерер |
| **4** | Редактор, статика | таймлайн, канвас, свойства, макет, «Примерить» | средний |
| **5** | Правила в редакторе | автоматика как часть сценария, призраки | низкий |
| **6** | Анимация | ключевые кадры, дорожка анимации, пресеты | высокий |
| **7** | Миграция профилей | `scenario_id` вместо `profile` | средний: данные |
| **8** | RGBA-слой | сложная графика поверх | опционально |

Этапы 1 и 2 независимы и могут идти параллельно: первый — переноска, второй —
новый чистый код. Этап 3 — единственный, который может ухудшить то, что уже
работает, и потому идёт под защитой золотых тестов из этапа 2.

Критерий приёмки, одинаковый на каждом этапе до седьмого: **существующие джобы
рендерятся ровно так же, как рендерились**. Пока это так, новый редактор ничего
не ломает, а когда перестанет — будет видно, на каком шаге.
