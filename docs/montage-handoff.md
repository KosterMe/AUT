# Передача: с чего начинать работу над сервисом монтажа

Этот файл — вход для сессии, которая начинает реализацию с нуля. Он ничего не
объясняет по существу: всё существо в двух других документах, и переписывать их
здесь значило бы завести третью версию правды.

---

## 1. Что уже есть

**Только проектирование. Кода нет ни строки.** В `docs/` лежат два документа,
и оба — источник истины:

| Файл | О чём |
| --- | --- |
| `montage-decisions.md` | **зачем** эта работа и **что решено** — 71 пронумерованное решение, `Р-01`…`Р-71`. Читать первым |
| `montage-service.md` | **как** — модель, компиляция, рендерер, расширяемость, редактор, ловушки, этапы. 16 разделов, ссылки вида `§N` |

Порядок чтения: `montage-decisions.md` целиком (он короткий), затем в
`montage-service.md` — §1 (три идеи), §3 (что растворяется), §8 (расширяемость),
и дальше по мере надобности. §15 — картина готовой системы, если нужно быстро
понять, к чему всё идёт.

Работа велась на ветке `claude/ecstatic-mendel-f217vc`. Если она не влита в
`main`, начинать с неё.

## 2. Зелёная база

```bash
pip install -r requirements.txt
python -m pytest -q          # должно быть 364 passed
```

Не пропускать `imageio-ffmpeg`: без него ffmpeg в контейнере может отсутствовать,
и два теста (`test_compiler.py::TestSoundtrack`, `test_encoders.py::TestRealProbe`)
падают не по делу. Всё нужное уже перечислено в `requirements.txt`.

**364 зелёных теста — это пол, а не цель** (Р-48). Ни один этап не имеет права
закончиться на меньшем числе.

## 3. Порядок работы

Полная таблица — §13 и Часть IV в `montage-decisions.md`. Коротко:

| | Этап | Суть |
| --- | --- | --- |
| **0** | Зонд ffmpeg | Скрипт прогоняет каждую конструкцию из таблицы §7.3 через целевой билд и печатает, что прошло. Таблица собрана **по документации**, а не по факту — на неё нельзя опираться, пока не подтверждена |
| **1** | Расцепление | Каттер решает только про свой транскрипт; `render_options` уходят из `SliceSpec` (Р-06) |

| **1в** | Сеть | Тот же клиент поверх HTTP, свой контейнер и своя БД (Р-03, Р-04, Р-67) |
| **2** | Модель и реестры | `compile(scenario, facts)`, реестр с conformance-тестом, `required_facts`, шаблон по умолчанию, золотые тесты |
| **3** | Слои, звук, обложка | `Frame` с трансформацией, расцепление звука (Р-18), обложка кадром (Р-58) |

новый чистый код.

## 4. Что не переобсуждать

Решения из `montage-decisions.md` приняты и обоснованы. Если по ходу реализации
выяснится, что одно из них неверно, — это нормально, но тогда **правится
документ**, с новым номером и причиной, а не молча код.

Отдельно, чтобы не предлагать заново:

* **Р-51** — приколоть рендер к версии шаблона: **отложено**, с тремя условиями
  возврата. Не «забыли».
* **Р-52** — безопасные зоны площадок: **отклонено**.
* **Р-53, Р-54** — связь «шаблон → просмотры» и многопользовательность: вне
  проекта.
* **Р-55** — вложенные сценарии, маски, 3D: последними, они единственные требуют
  изменения талии.

## 5. Что стоит дороже всего, если проглядеть

1. **Ключ кэша фрагментов** (§7.5, Р-30). `speed` и эффекты сегмента обязаны в
   него войти; `look`, накладки и переход — обязаны не войти. Ошибка в первую
   сторону молча отдаёт старую картинку — не падает, не логируется, обнаруживается
   глазами через неделю.
2. **Правило узкой талии** (Р-35). Фича меняет `Element`/`Track`/`Frame`/
   `Anchor`/`Duration`/`Composition` только если её **нельзя** выразить записью
   реестра. Не «неудобно» — нельзя. Каждое нарушение удорожает следующую фичу.
3. **Неизвестные параметры при чтении сохраняются** (Р-39). Выбросить — значит
   молча уничтожить чужую работу.
4. **Порядок подстановки и экранирования** (§16.3). Сначала подставить `{title}`,
   потом экранировать результат целиком. Обратный порядок превращает название
   ролика в управляющую последовательность ASS.
5. **Нулевая регрессия по умолчанию.** Статический `Frame`, все переходы «стык»,
   все `roll_sec` нулевые — граф фильтров обязан совпадать с нынешним. Это и есть
   способ проверить, что обобщение ничего не сломало.

## 6. Как работать

Критерий приёмки одинаков на каждом этапе до седьмого: **существующие джобы
рендерятся ровно так же, как рендерились.** Пока это так, новый редактор ничего
не ломает; когда перестанет — видно, на каком шаге.

С этапа 1в это перестаёт быть намерением: старый хендлер живёт рядом с новым один
релиз (Р-67), значит один и тот же клип можно отрендерить обоими путями и сравнить
файлы.
